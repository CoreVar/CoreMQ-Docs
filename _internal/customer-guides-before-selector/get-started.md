# Install CoreMQ and send your first message

Use this path for an isolated evaluation. For cloud installations, start with [deployment choices](deployment.md); the Marketplace packages have different prerequisites and release status. Record the broker version and edition from **Configure > About**. Obtain the broker and CLI from the same approved release; these docs do not provide a public download for an unreleased candidate.

> [!NOTE]
> This walkthrough uses a disposable local broker. Complete the deployment and security checks before using an installation for active workloads.

## Local installation

Extract the approved OS/architecture package into a directory you control. The broker executable is `coremq-broker`; `coremq` is its management CLI. A self-contained package includes its runtime. A framework-dependent build needs the .NET version specified by that build (the reviewed development source targets .NET 10).

From the extracted broker directory:

```powershell
./coremq-broker --data-dir ./coremq-evaluation --http-port 18080 --mqtt-port 11883
```

Open `http://localhost:18080`. The reviewed local build initializes username `admin` and password `coremq-local` on a new database. These are public development defaults. **Local mode binds HTTP and MQTT to all interfaces**, despite printing localhost addresses. Use an isolated workstation/network, or Docker's loopback-only port mappings below. Do not expose this startup to the Internet. Change the administrator password under **Configure > Identities** before allowing any other machine to reach it. Changing the startup defaults does not rotate an existing account.

The local build uses SQLite and standalone message/session stores. It does not include the CoreControl connector. A local data directory preserves configuration; do not assume it provides the cloud Redis session durability. Stop the process cleanly before copying its SQLite database. See [backup and restore](backup-restore.md).

## Docker evaluation

Use an approved **local-edition** image and its immutable digest. Replace the placeholder; do not use an AWS/Azure/GCP metered image for this local walkthrough. Those images have different startup and entitlement requirements.

```powershell
docker volume create coremq-evaluation-data
docker run --name coremq-evaluation --detach `
  --publish 127.0.0.1:18080:8080 --publish 127.0.0.1:11883:1883 `
  --mount source=coremq-evaluation-data,target=/data `
  --entrypoint dotnet registry.example.com/coremq/local@sha256:<approved-digest> `
  coremq-broker.dll --data-dir /data --http-port 8080 --mqtt-port 1883
```

This form is for a .NET DLL image whose executable is `coremq-broker.dll`; inspect your approved package's entry point if it differs. The volume must be writable by the image's runtime user. The image reference and storage ownership are release inputs, not generated by this guide. Loopback mappings allow this workstation to connect without exposing the container ports externally. Do not log real configuration or secrets to debug a failed start.

## Secure first setup

1. Change the initial administrator password. Keep a separate local recovery account protected and tested before enabling external sign-in.
2. Under **Configure > Global Policies**, set an explicit default deny policy for ordinary application topics. Define a narrow role for the first client and allow only `demo/first`; review [policy precedence](policies.md) before assigning it.
3. Under **Configure > Identities**, create a separate MQTT account, assign that role, and omit management roles. Administrator privileges and message permissions are independent.
4. Review **Configure > Endpoints**. For an isolated loopback test, the basic MQTT listener can be used. For any remote client, configure TLS with a valid hostname certificate and close plaintext ports; follow [endpoints and certificates](endpoints.md).
5. Connect the CLI to the HTTP management origin. It prompts without echoing the password:

```text
coremq connect http://localhost:18080 --username admin
coremq about
coremq health ready
coremq endpoints list
coremq status --output json
```

Use HTTP only for this isolated loopback evaluation. Use HTTPS for remote management and provider administration. Protect the saved bearer-token file and disconnect after evaluation.

## Prove client access

Use your MQTT client's protected credential input rather than putting passwords in process arguments. Subscribe to `demo/first` at QoS 1, then publish `hello from CoreMQ` from a second client. Confirm the subscriber receives exactly that payload. The [Azure guide](azure/setup.md#send-a-first-encrypted-message) includes a Mosquitto configuration-file example for a TLS deployment; check your installed client's help for its supported file option.

Then test a publish and subscribe outside the allowed topic. Both must be denied by your intended policy. Confirm the identity appears under **Connections** while connected. A Ready health response proves dependencies are reachable; it does not prove your client's certificate, credentials or topic permissions work.

Stop the evaluation with `docker stop coremq-evaluation` and remove only that owned container with `docker rm coremq-evaluation`. Keep the data volume until you have decided whether to retain or back it up. Volume deletion is a separate, irreversible data action. See [uninstall](upgrade-uninstall.md).
